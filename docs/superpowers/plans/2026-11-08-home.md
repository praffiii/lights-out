# Home Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the Home design (Figma) on the real app: the shell every page shares (loader, Header B with the live weekend box, menu, footer, page change, theme) and Home's five sections, with the circuit band following the real calendar.

**Architecture:**
- The motion spike `spikes/motion-home` is the reference implementation. Port its files; don't rewrite them. Its motion is what Praffi approved.
- Home is prerendered to static HTML. Everything that depends on the browser (theme, reduced motion, hover) or on live data (the weekend box and the circuit band) renders on the client after mount, behind the loader.
- The two live parts are pure functions of `(SeasonSnapshot, now)`, computed in the browser every second, so a 30-minute-old snapshot still shows the right state.
- Each circuit is built once in Blender and looked up by Jolpica's `circuitId` in a typed registry.

**Tech Stack:** The foundation plan's stack (TanStack Start on Cloudflare Workers, TanStack Query, Effect, `bun test`), plus GSAP 3.15 with ScrollTrigger, SplitText and CustomEase, `@gsap/react`, Lenis, React Three Fiber 9 with three, `@playwright/test`, Blender 4 (headless) and `@gltf-transform/cli`.

**Spec:** `docs/superpowers/specs/2026-11-07-f1-fan-site-design.md`. Also read `DESIGN.md` (system, Header B, weekend box) and `docs/motion-map.md` (Shell and Home rows).

**Prerequisite:** `docs/superpowers/plans/2026-11-07-foundation-season-data.md`, Tasks 1–4 and Task 5 Steps 1–3. That plan provides the app, `SeasonSnapshot`, `/api/season` and `useSeason()`. Its deploy moved to Task 7 here.

## Global Constraints

- Everything in the foundation plan's Global Constraints applies: zero cost, `*.workers.dev`, no `any`, exact footer disclaimer, ask before any Cloudflare action, **no comments in code, no type assertions, and `bun run lint` passing before each commit**.
- **Porting the spike.** The spike and the saved Blender scripts are full of comments and `as` casts. Strip every comment while porting, and replace each cast with a typed API or a runtime check: `querySelector<HTMLElement>()`, `Number(gsap.getProperty(...))`, `instanceof THREE.PerspectiveCamera`. When a comment explained *why* (the `ONCE` crash, the pin order, the meshopt settings), make sure that reason is in `docs/motion-map.md`, `DESIGN.md`, a test name or the commit message before deleting it.
- **Commits.** Praffi said not to commit or push until they say so. Ask before this plan's first commit, and never push without their word. The commit steps below give the message to use.
- **React `~19.3.x`.** React Three Fiber 9 needs React ≥19.0 and <19.4. Pin React and react-dom to `~19.3.1`, as the spike does.
- **One clock.** Lenis, ScrollTrigger, every tween and the R3F canvas (`frameloop="never"`) tick from `gsap.ticker`. No `addEventListener('scroll')` and no `requestAnimationFrame` loops of your own.
- **Every move lives in `src/motion/motion.ts`** (`sweep`, `reveal`, `block`, `draw`, `roll`, plus the CSS hover roll). No section invents its own.
- **Never `once: true` on a ScrollTrigger.** Use `ONCE` (`toggleActions: 'play none none none'`). A once-trigger kills itself inside `refresh()` when the page loads already scrolled, and crashes the page ("reading 'end'").
- **Prerender-safe.** No `window`, `document`, `matchMedia`, `localStorage` or `location` at module level or during render. Read them in effects, or through `useMounted()`.
- **A refresh starts at the top.** The head script sets `history.scrollRestoration = 'manual'`.
- **Links to pages that don't exist yet** render as text with a muted "Soon" label in place of "Read →" or "→". **[my call]**
- **Photos:** the spike's Wikimedia Commons files in `spikes/motion-home/public/img`, each with its place, year and Commons credit on the page. **Facts:** Praffi checks every circuit fact and every line of copy before deploy.
- Scripts that call the network send `User-Agent: LightsOutFanSite/0.1 (personal project)`.

## Review Focus

1. **Prerender or hydration breaks on browser-only values.** Expect `bun run build` to succeed, and the console to show no hydration warnings in light, dark or reduced motion. Tested in Task 1.
2. **Refresh mid-page or at the footer.** Expect the page at `scrollY 0` from the first frame, the loader, then the hero, with zero page errors, at 1470×830 and 390×844. Tested in Task 2.
3. **`/api/season` warming (503), down or slow.** Expect Home to render fully without the weekend box or the circuit band, with no errors, and the loader to lift within 2.6 s. Tested in Task 6.
4. **The next race's circuit has no model** (for example a 2027 newcomer). Expect the circuit band to be left out, not broken, and the registry test to name the missing circuit. Tested in Task 4.
5. **Timezones, DST and TBC times.** Expect the countdown to use real instants. "Your time" uses the visitor's timezone and "track time" the circuit's. A session with no confirmed time shows "Time TBC", never midnight. Tested in Task 5.

  - `CIRCUITS: Record<string, CircuitInfo>`, keyed by Jolpica `circuitId` (`interlagos`, `vegas`, `losail`, `yas_marina`, `albert_park`).

    ```ts
    type CircuitInfo = {
      model: string; name: string; gp: string; tz: string;
      corner?: { turn: number; name: string };
      facts: { firstGp: number; lengthKm: string; laps: number; distanceKm: string; turns: number; direction: 'clockwise' | 'anticlockwise' };
    }
    ```

    - `model` is the bacinger id. `name` is the short name used in the heading, such as "Interlagos". `gp` is the broadcast name, such as "São Paulo GP". `tz` is the IANA zone.

    - `this-weekend`: now falls between the race's first session `startsAt − 48h` and the race `startsAt + 4h`.
    - `next`: the next race after that window, including next season's round 1 once it is published.
    - `finale`: the season's last race, once the season is over and no new calendar has been published.

- Produces:
  - `SESSION_MINUTES: Record<SessionName, number>` = FP1 60, FP2 60, FP3 60, SprintQualifying 45, Sprint 60, Qualifying 60, Race 120.
  - `boxState(s: SeasonSnapshot, now: Date): BoxState`, where

    ```ts
    type BoxState =
      | { kind: 'live'; gp: string; session: SessionName; leftMs: number }
      | { kind: 'after'; gp: string; session: 'Qualifying' | 'Sprint' | 'Race'; winner: string }
      | { kind: 'before'; gp: string; session: SessionName; inMs: number; confirmed: boolean }
      | { kind: 'between'; gp: string; days: number }
      | { kind: 'over'; season: number }
    ```

    - `live`: a session has started and not run past its `SESSION_MINUTES`.
    - `after`: for 2 h after a qualifying, sprint or race ends, and only if the snapshot already holds that session's result. Practice has no results in Jolpica, so it never shows an "after" state.
    - `before`: inside `pickRace`'s this-weekend window, otherwise.
    - `between`: outside the window, with a next race.
    - `over`: no next race at all.
  - The box copy follows DESIGN.md: "São Paulo GP | Practice 3 in 02:14:07", "● Live | São Paulo GP | Practice 3 41:12 left", "São Paulo GP | Race P1 Antonelli", "Next Las Vegas GP | in 12 days".
